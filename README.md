## 先回答：WordPress 到底吃多少资源

WordPress 的瓶颈通常不是 CPU，是内存和数据库查询。

PHP-FPM 每个进程都要占内存，装了缓存插件、安全插件、表单插件之后，1GB 内存的机器很容易在几十个并发时把进程撑爆，表现就是访问一会儿白屏一会儿正常。这也是为什么很多人的第一台 1核1G 机器用半年就得换。

大致可以按访客量对号入座：

| 站点情况 | 建议配置 | 硬盘起步 | 说明 |
| --- | --- | --- | --- |
| 个人博客、日访问 100 以内 | 1核2G | 20GB SSD | 1核1G 能跑，但后台会明显卡，插件一多就危险 |
| 企业官网、日访问 100–1000 | 2核2G 起 | 40GB SSD | 这个区间是 2G 内存的分水岭，别硬省 |
| 内容站、带 WooCommerce | 2核4G 起 | 80GB SSD | 电商插件写数据库很频繁，缓存和内存都要给足 |
| 日访问 1000+ 或跑多个站 | 4核4G / 4核8G | 160GB SSD | 到这一步该考虑对象存储和 CDN 分担静态资源了 |

硬盘优先选 NVMe/SSD，20GB 是底线——WordPress 本体不大，但主题、插件、图片和备份很快就会吃掉空间，磁盘 IO 差还会直接拖慢后台。

实际做法很简单：在购买页选好套餐和付款周期，把你能找到的码填进优惠码框，点一下 Validate Code 验证——通过了就是有效，没通过就别纠结，按页面显示的价格下单。**不要为了用一个不确定的优惠码去凑付款周期**，年付锁死的是更长的钱，除非你确定这台机器会长期用。

## 装好 WordPress 之后的几个必做动作

很多人买完 VPS 就卡在环境这一步。用宝塔或 1Panel 之类的面板搭 LNMP 环境，半小时能跑起来，但下面几个参数不改，性能会白白浪费：

1. **PHP 选 8.2 或 8.3**。同一套环境下，PHP 从 8.0 升到 8.3，每秒请求数大约能提升两成左右，前提是主题和插件兼容。升级前先备份，并确认插件作者声明了兼容版本。
2. **调大 opcache 和 php-fpm 的进程数**。`opcache.memory_consumption` 给足，后台响应速度肉眼可见地变快；`pm.max_children` 要按内存算，1G 内存的机器别照抄 4G 机器的配置，进程数开太多反而会被 OOM 杀掉。
3. **开 Nginx FastCGI 缓存**。WordPress 是动态程序，缓存命中之后首字节时间能压到几百毫秒以内，静态页面基本是直接吐出来。
4. **换掉默认的 128M 内存限制**。有些镜像默认 `memory_limit = 128M`，装插件时容易报 500，改成 256M 更稳。
5. **备份放在机器之外**。DMIT 的流量跑完只是降速、不会停机，这一点很省心，但它不替代备份。插件升级、主题改错、误删文件都可能导致数据丢失，异地备份该做还是得做。

## 常见问题

**1核1G 能跑 WordPress 吗？**
能，前台访问量不大的博客没问题，但后台和插件会明显发卡。如果你打算装缓存、安全、SEO 三个以上插件，直接上 1核2G 或 2核2G，省下来的时间比省下来的钱值钱。

**香港还是洛杉矶？**
访客集中在国内、对延迟敏感选香港；预算有限、或者延迟 140ms 左右可以接受，洛杉矶 Pro 性价比更高，同样的钱能拿到更大的带宽和流量。两边差价不小，先想清楚访客在哪。

**流量跑超了会怎样？**
DMIT 的处理方式是降速而不是停机，超出后按套餐降到 4Mbps 到 10Mbps（T1 系列能到 100Mbps 以上）继续跑。网站不会挂，但图片站、视频站这种吃带宽的场景会明显变慢，流量大的站还是提前算好。

**免备案会不会影响百度收录？**
服务器在境外，走的是正常域名解析，能不能被收录主要取决于内容质量、访问速度和百度站长平台的主动提交，跟备案没有直接的因果关系。反过来，如果站点要接国内支付、投国内广告，备案的实际价值就大得多，这时候该考虑国内机房。

**为什么同一机型有 AS3、AN4、AN5 三个版本？**
这是硬件平台代次，AS3 是 AMD EPYC 7003，AN4/AN5 更新，性能更强、价格也更高。用来跑 WordPress 的话，AS3 的 Zen 3 平台单核性能完全够用，价格门槛更低，是建站场景里比较划算的一档。
